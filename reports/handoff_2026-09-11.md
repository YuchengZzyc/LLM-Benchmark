## 2. 核心问题：为什么本地分数远低于官方模型卡

| 本地任务 | 本地(×100) | 官方 | 差距定性 |
| --- | --- | --- | --- |
| mmlu_redux | 23.3 | 88.8 | 生成式+抽取失败 |
| mmlu_prox_en / zh | 18.6 / 37.4 | 71.5 | 同上 |
| ceval / mmmlu_zh | 24.1 / 23.5 | 85.1 / 76.1 | **loglikelihood 口径塌到随机**(4选1=25) |
| gsm8k strict / flexible | 40.0 / 20.0 | — | 前导+抽取污染(strict>flexible 反常) |
| mgsm_zh flexible | 60.0 | — | 抽取成功即正常 → 管线无误 |
| ifeval | 13.3 | 89.8 | 前导+格式不符 |
| LongBench v1 ×12 | 0–16 | (v2) 50.0 | 官方 64–512 上限×前导 → 全灭 |
| aime24/25 | 0.0 | (HMMT) 74/76.8 | 竞赛难度+超长 CoT 截断+限量 |

**原因 1（显示单位，非问题）**：lm-eval 报 0–1 小数，官方报百分数，×100 后对齐。
与量化无关——本地跑的是原生 bfloat16（发布精度）。

**原因 2（thinking 前导）**：Qwen3 系 chat template 默认开 thinking；实测模型先输出
400–6000 字符 "Thinking Process" 前导才给答案。后果链：512 上限时 gsm8k 仅 0.05 →
2048 恢复 0.40（管线敏感性证明）；gsm8k strict 0.40 > flexible 0.20 反常（flexible
抽"最后一个数字"被截断推理尾部污染）；LongBench 官方 64–512 token 上限下前导直接
耗尽额度 → 全维接近 0。

**原因 3（选择题口径）**：ceval/mmmlu 走 loglikelihood（同时报 acc+acc_norm 为特征），
后训练模型"先推理再作答"的训练方向与"直接压答案 token 概率"相反，掉到≈随机是
chat 模型已知现象。官方数字为生成式口径。**关 thinking 不会修复此项**，中文知识的
可比信号应看 mmlu_prox_zh（生成式）。

**非主因**：限量 30 条只贡献 ±9% 噪声；mmmlu 跑满 1710 条 stderr 仅 ±1%，
23.5 vs 76.1 是口径差异非采样差异。权重与模型卡不符不能 100% 排除，但全部失败
模式指向口径而非权重（抽取成功通道 mgsm 0.60 / math_verify 0.40 均正常）。
